# 先把一个小入口做出来

2026-09-16 · 第一篇开发记录

Dao-Shell 从一个很具体的问题开始：如果我只是想找一份文件、整理几个下载，或者看看电脑为什么卡，能不能先说一句话，再决定怎么操作？

我们把首版范围收得很小。LLM 是主要入口，可以理解上下文、追问和调用工具；Shell 负责把电脑上的实际对象、操作方案和结果呈现出来。人仍然决定是否修改文件。

## 这次做出来了什么

一个能运行的 Windows 命令行原型：查找文件、选择对象、提交打开请求、确认后移动，以及观察当前资源。没有模型时，还能用一个很小的直接搜索入口。

文件移动用临时测试目录实跑过。模型循环则先用本地模拟服务验证“两轮对话、引用同一个文件、确认、移动、回传结果”。**这证明了协议与执行流程能接起来，不证明真实模型已经好用。**

目前 21 个本地测试通过，便携包在本机移除开发工具 PATH 后也能运行。真实模型与干净 Windows 环境验收仍在路线图上。

## 一个真的踩到的问题

一开始，我们以为持有目录句柄就能阻止目录被替换。测试却发现，只申请读取属性时，目录仍然可能被改名。

于是调整了句柄权限，并保留这个回归测试。另一个测试让批次中的第二个文件无法移动，检查程序会不会诚实报告：第一个已完成、第二个失败、第三个未开始。

这些结果比“看起来已经成功”的一段回答更重要。人需要据此决定下一步。

## 暂时不做什么

首版不包含应用安装。它有另一套生命周期与确认问题，不应该拖住文件操作的第一条闭环。Everything 也先作为可选加速，限定目录扫描足够让我们开始验证。

我们也没有把它做成另一个完整 Agent 工作台：没有长期 Goal、编程流程和后台自主任务。后续是否增加能力，先问它是否直接帮助人使用电脑。

## 接下来想知道

真实模型能否稳定理解“上周”“第二个”“刚才那几个”？第一次设置是否太麻烦？确认方案有没有把信息说清楚？遇到失败，人是否知道该怎么继续？

下一轮会围绕这些问题做试用。欢迎通过 [Issues](https://github.com/kestiny18/Dao-Shell/issues) 留下你实际想完成的电脑操作。

项目方案和代码实现使用了 Codex、ChatGPT 辅助。模型之间的评审是设计输入；验证结果和对外承诺仍由维护者负责。
