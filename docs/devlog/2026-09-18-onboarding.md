# 让模型配置在向导里完成

Windows 试用暴露的一个问题是：即使提供 setup，用户仍要理解完整接口地址、环境变量名，再退出程序设置密钥、运行诊断、重新启动。配置字段逐项提问，并没有完成首次使用体验。

这次把流程收敛为：运行 daosh → 选择服务 → 隐藏输入密钥 → 选择连接验证 → 选择查找目录 → 保存并开始对话。

DeepSeek 提供可修改的地址和模型预设，自定义服务和本地模型仍然保留。预设依据 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/)及其[模型列表](https://api-docs.deepseek.com/api/list-models/)，服务变化后仍可修改地址或模型，不把预设当成兼容性保证。

密钥可以只在当前进程使用，也可以明确选择保存到 Windows 凭据管理器。使用 [Windows 通用凭据](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw)，限定当前用户、当前电脑，并绑定完整接口地址。密钥不写入配置文件或操作记录。切换地址时重新取得对应密钥，不隐式沿用刚输入的旧服务密钥。

连接验证继续使用最多两次固定虚构请求。失败后可原地修改密钥、地址和模型；不会读取真实文件来测试。向导只增加读取范围，不增加写入权限。用户可取消、跳过模型或跳过验证；界面会说明未验证状态。

自动测试覆盖本地服务返回鉴权失败后重输密钥再通过工具协议验证、无效目录修复、取消、凭据隔离与 Windows 凭据读写。真实提供商的完整自然语言场景与干净 Windows 环境验收仍待完成。
