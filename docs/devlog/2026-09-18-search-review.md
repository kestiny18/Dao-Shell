# 先把“找到那个文件”做好

这轮依据真实试用和代码审核，收敛到已有搜索链路，没有新增 Agent 工作台或索引后端。

- 读取、写入范围分别消除已被父目录覆盖的子目录；有效读取范围包含可写目录。不会因此扩大写权限，也不会把前缀相似的兄弟目录合并。
- 每次新搜索都替换数字候选，零结果、参数错误和取消也清空。历史对象引用仍可用于明确的自然语言指代，操作前继续核对身份。
- 模型工具增加 `terms`、`match_mode` 和 `kind`。例如 `terms=["客户端", "初始化"]`、`extension="sql"`、`kind="file"` 能匹配相对路径 `示例项目/客户端初始化/dump-client.sql`，无需文件名含“初始化”。默认按相关度排序；原 `query` 保留文件名包含匹配，直接 CLI 参数保持兼容。
- 相同路径且身份、大小和修改时间均未变化时复用引用；文件改变或被替换会产生新引用，旧引用不会被静默刷新成新对象。
- 资源工具增加由程序格式化的 `facts_for_explanation`，与终端共用单位转换。模型被要求引用这些事实，不重算、不混合多次采样。此约束仍需真实模型验证，不能保证模型永不误述。

路径含义不明确时，提示模型优先查看源文件附近并尽早追问；不要把空关键词全量列举作为常规退路。移动继续只支持同卷，补充写权限不能解决跨卷限制。本轮未改移动执行器，也未新增全量阻断原因汇总。

使用独立临时目录验证父子范围压缩、多关键词路径命中、类型过滤、相关度排序，以及超过 2000 次重复发现不会消耗新对象名额。该夹具一次搜索命中初始化脚本，不代表真实模型已经能稳定用一到两次调用完成任务。全局 5 秒扫描预算仍保留，大目录覆盖率还需继续实测。
