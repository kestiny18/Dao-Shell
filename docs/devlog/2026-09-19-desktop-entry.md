# 让第二个入口走通同一条文件链路

之前的文件索引实验回答了部分查询和更新问题。这一步先不把索引接进来，而是让
“说出想找的文件，看到候选，再确认打开”出现在一个实际可用的窗口里。

Tauri 在这台 Windows 机器上已经构建并运行。窗口沿用 CLI 的模型配置和目录范围，
默认自然语言输入，也保留明确的文件名搜索选项。桌面只开放查找、元数据检查与打开。

第二个入口也帮助我们找到了值得提取的接口：会话输入、真实候选、模型历史和取消状态。
文件范围与身份核对仍由已有核心负责，桌面只负责展示与收集确认。每次确认绑定当前
对象和一次性请求，过期、取消或切换会话后不能拿旧选择继续操作。

验证过程中发现，对话变长后底部的停止按钮会滚到窗口之外。因此把输入区固定下来，
只让上方内容滚动。另一个小调整是单独标注“本地回执”，避免系统实际反馈和模型复述
看起来像同一种证据。系统接受打开请求，仍不等于已经验证目标应用展示了文件。

目前原生窗口使用本地固定响应模型与合成文件验证，不能据此宣称真实模型体验已经通过。
也没有加入全局快捷键、托盘服务或 GUI 设置页。下一步先用已有模型试用，记录查找
命中、等待时间与确认是否顺手，再决定增添什么。
