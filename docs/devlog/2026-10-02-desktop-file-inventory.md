## 实现与修复

桌面设置可显式登记、更新、停止及移除加速目录；进程内 SQLite 元数据快照接入既有搜索，监听在扫描前建立，普通文件事件合并更新，歧义/目录变化/溢出完整校准，另有五分钟周期与失败退避。权限、根身份、候选身份仍实时校验，取消和移除使晚到任务失效。缓存位于扫描根之外，只保存元数据，移除不删除源文件。

仅当所有请求根精确匹配可用登记时，普通 query、原四种排序及分页加速；terms、类型/扩展名/时间/大小过滤、未登记或子目录根，以及更新期间整体回退原扫描，不缩小默认范围。模型常用 terms，因此自然语言请求尚不保证加速。建库预算为十万访问条目或六十秒，包含目录，达到后暂停自动重试。

T3 暴露并修复两处边界：首次扫描完成后积压通知处理完毕才发布可用状态，避免短暂可用后立即重建；最终 Reply 携带完整 search_receipt，前端与事件回执去重应用，防止 IPC 事件晚于 Reply 时丢失来源/覆盖。过期请求保护仍保留。后端计时拆分 discovery_ms（含快照读取/克隆）和 validation_ms（候选身份校验）。

## 试用与限制

先用新建隔离配置和合成目录启动独立产物（设置 DAO_SHELL_DESKTOP_CONFIG），模型留空；设置 → 文件搜索添加该配置已授权的普通目录，等到可用后输入文件名，检查来源说明。新建/改名合成文件再搜索；立即更新期间可切换页面并观察现场扫描；停止后需手动更新或重启恢复；移除只清理缓存。不要复用用户后来使用的 `.tools/p9-t1-fixture` 配置。

随后用户可自行选择一个已授权的普通常用目录试用只读搜索。记录缓存含本地路径；索引是事件辅助观察，打开/移动仍以现有实时身份、权限和确认边界为准。原生目录选择器仅有 T1 添加与状态人工观察；T3 使用真实 WebView/后端，但没有逐项人工点击全部控件。OS ACL 特殊拒绝、网络盘、云占位文件、系统调用长时间阻塞、百万规模、长期五分钟校准浸泡、安装包/干净机器与独立验收未验证。下一轮优先收集实际根覆盖率、terms 查询占比和更新延迟，再决定是否扩展加速语义。
