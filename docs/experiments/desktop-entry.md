## 这一步验证什么

默认自然语言输入，展示真实文件候选，选择文件后确认打开，显示本地回执。
无模型文件名搜索是显式回退。暂不加入整理、编程、Goal、托盘或后台自主任务。

第二个入口复用现有 `Dialogue`、`Runtime`、范围判断、文件身份核对和打开规则。
新增进程内 `FileSession`，承载输入、候选和模型历史；CLI 暂保留原有会话装配。
这一步提炼的是实际需要的文件入口接口，尚未形成通用 SDK。

## 接口与边界

- `Say / Search / Open / Reset` 是入口动作。桌面模型仅声明搜索、元数据检查、打开三个工具；运行时分发再次限制，模型伪造其他工具也不能执行。
- 配置中的读、写目录均可作为查找范围，桌面会话的写权限为空。
- 每个会话独立保存候选、模型历史与取消信号。对象 ID 不能跨会话使用；重置、空结果会使之前的候选选择失效。
- 打开确认绑定当前对象与随机一次性请求 ID，90 秒过期。取消、关闭窗口使待确认失效；执行前仍由现有 Runtime 核对文件身份。
- 桌面适配器同时只处理一个请求，耗时调用放在工作线程。取消信号在接收请求时初始化，工作线程不得再次清除，避免吞掉早到的取消。
- Tauri 仅向本地窗口开放四个应用命令，未加入文件系统或 shell 插件。前端以纯文本渲染模型输出和路径，不持有密钥。
- 目前 Runtime 仍要求 Journal；只读文件会话使用独立临时空 Journal，不锁定 CLI 的持久操作记录。若未来接入写操作，必须重新设计持久记录与恢复路径，不能沿用此临时策略。

## 验证与限制

本机 Windows GNU 工具链已构建并启动原生 Tauri/WebView2 窗口。
本地固定响应模型驱动真实文件搜索与确认流程，已观察到：

- 搜索两份合成文本文件，展示真实候选和路径。
- 拒绝打开后显示未提交请求；确认后显示系统已接受打开请求。
- 空结果后清除之前的候选，不能继续点击旧选择。
- 延迟模型请求期间点击停止，显示本轮已取消并恢复输入；随后新会话清空对话并回到初始界面。

本机根包 59 项测试通过、1 项负载测试默认忽略；桌面包 1 项确认状态测试通过。
根包与桌面严格 Clippy、格式检查通过，前端及夹具 JavaScript 语法检查通过。
