## Goal / Scope

用户选择常用目录后，桌面端保存文件记录；继续使用现有输入框查找，减少反复遍历目录的等待。先交付可试用闭环，再依据实际目录规模、搜索命中和更新延迟迭代。

第一版只支持普通权限下的本机普通目录，保存路径、文件名、类型、大小、修改时间和文件身份，不读取文件正文。模型可用时仍由模型理解请求并调用同一搜索能力；无模型或模型不可用时沿用 P3 的文件名搜索路径。索引加速不依赖模型。

## Existing evidence

- [索引实验](../experiments/file-inventory.md)已有 SQLite 持久快照、事务重建、普通权限通知和周期校准；尚未接入桌面正式搜索。
- `src/runtime.rs` 的 `file_search` 当前调用 `files::search` 实时遍历目录。
- 实验查询只有路径子串匹配和路径排序，不能直接代替正式搜索的筛选、相关度、分页等语义。
- 既有 2 万文件实验只能说明特定样本的潜力，不能作为桌面端到端性能或全机规模承诺。

## User experience

1. 设置新增“文件搜索”区域，提供“添加加速目录”，使用现有原生目录选择方式。只允许当前读取范围内的目录；选择目录本身不授予新权限。
2. 添加后后台建库；列表展示目录、已记录数量、状态、上次完成时间。建库期间可以继续使用现有搜索和其他桌面功能，不展示虚假的百分比。
3. 搜索仍用现有输入框。完整可用的记录优先用于搜索；未建库、更新未完成或失败的范围使用原有扫描。结果说明“已记录目录/现场扫描/混合来源”和未完成的范围，不能把局部无结果说成全范围无结果。
4. 每个目录只提供“立即更新”“停止本次更新”“移除”。停止后保留旧快照并标注待更新，下次更新由用户操作或下次启动恢复；不会立即自动重启被停止的任务。
5. 移除后停止监听和更新，删除本应用对应的索引缓存，不删除源文件。移除加速目录不改变原有读取权限，也不等同禁止普通搜索。
6. 应用重启保留目录配置和快照；检查目录身份、访问权限后后台校准。退出应用后不继续扫描，下次启动补齐离线期间的变化。

状态用用户语言：首次记录中、可用（附上次更新时间）、更新中、待更新、记录不完整、目录不可访问。事件辅助更新也不承诺记录绝对实时或完整。

## Decisions / Constraints

- 复用进程内 Rust 能力，从实验抽取必要模块；不运行实验 CLI 作为后台服务，不引入守护进程、开机服务或管理员权限。
- 第一版支持多个明确选择的目录；重叠目录规范化去重，后台全量扫描串行，查询使用已提交快照，不持有桌面会话锁进行长扫描。
- 保持现有 `file_search` 请求语义。初版仅对已证明等价的查询使用索引；不支持的筛选、排序或分页组合整体回退原有扫描，不能静默忽略参数。
- 跨目录查询统一去重、排序、分页，不把每个目录的第一页简单拼接。混合查询仍可能受未建库目录拖慢，不承诺全部查询同样快。
- 数据库存在应用数据目录，位于被扫描目录之外；若无法满足则拒绝启用该目录并解释原因。数据库是含路径信息的本地缓存，不上传、不保存正文。
- 全量更新成功后原子切换代际；取消、预算耗尽或失败保留上一份快照。记录不完整时展示缺口，不推断未观察到的文件已删除。
- 查询前检查当前权限与根目录身份；权限收紧后不继续暴露越权的缓存路径。结果登记为当前会话对象前重新读取身份；打开、移动仍走既有权限、身份与确认流程，不把索引身份当执行凭据。
- 后台更新使用独立取消状态；停止一次会话请求不取消其他会话或索引，移除目录则使正在进行的该目录任务失效，禁止晚到结果重新发布。
- 初始扫描预算沿用实验的 10 万访问条目 / 60 秒；达到预算提示缩小目录，不能标为完成，也不反复自动重试。同一文件系统调用可能超过取消等待时间，不承诺硬超时。
