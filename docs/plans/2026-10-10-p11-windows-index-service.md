## 目标与范围

首次启用“全盘快速搜索”时通过 UAC 安装专用索引服务，此后桌面以普通权限搜索，本机在线固定 NTFS 卷自动发现、建库和更新，不要求逐目录登记。桌面退出后索引继续维护，电脑重启后服务恢复。

“全盘”表示自动覆盖受支持卷，不承诺读取未解锁卷、所有其他用户私密路径或所有正文。索引只包含名称、路径关联、文件身份及必要属性；文件正文读取、模型调用和文件操作不进入索引服务。

本轮只实现 Windows。macOS/Linux 不写占位后端，不做插件系统、通用 Agent daemon 或跨平台服务框架。以后通过平台采集适配器和进程启动适配器替换 Windows 实现。

## 架构与代码边界

```text
桌面 UI / 会话 / 模型（普通权限）
                  |
          IndexClient：有界查询、状态、取消
                  |
        Windows 本地命名管道（认证、版本、限额）
                  |
       DaoShellIndex 服务：索引生命周期与检索
           |                         |
    IndexStore / 查询引擎       WindowsVolumeSource
    SQLite 与索引代次         MFT / USN / 卷身份
```

建议在现有 Rust 工程内增加 `src/file_index/` 和独立服务 binary，不为此拆成多个仓库。原 `src/inventory/` 保留为目录级兼容实现；完成接入后才移除重复路径。

最小共用接口：

- `IndexClient.search(query, page_size, cursor, cancellation)`：返回候选、索引代次、覆盖范围、更新时间及不完整原因，不传回全盘数组。
- `IndexClient.status()`：服务版本、卷状态、进度、错误和兼容能力。
- `VolumeSource`：发现卷、首次枚举、从检查点读取变化、核对检查点。检查点由后端解释；上层不理解 USN 数值、盘符或 Win32 错误。
- 文件身份使用后端标识 + 稳定卷身份 + 原生文件身份；同一文件与多个名称/父目录关联分开，不能假设“一条文件记录只有一个路径”。

不设计统一 USN/FSEvents 原始事件模型。后端输出索引变更和“需要协调/重建”结果，允许未来平台通过局部扫描完成更新。

## 服务与权限

- 提权限于专用安装器及索引服务。先验证满足卷读取的服务账户与所需权限；若需要 LocalSystem，明确保留高权限边界并裁减不需要的权限，不能仅因代码只读就称为低权限进程。
- 服务文件安装到受管理员保护的 Program Files 子目录，数据放在受服务身份和管理员 ACL 保护的 ProgramData 子目录。普通用户不能替换服务程序、依赖库、配置或数据库。
- 安装器仅执行固定的安装、升级、修复、卸载操作；校验产品包/来源与版本，验证目标和重解析点，固定且正确引用服务路径。发布前准备代码签名；开发测试使用固定可审计产物。
- 本地命名管道显式设置 ACL，拒绝远程连接，核对客户端 token/session；身份不从请求正文中的 SID、PID 或用户名推导。客户端同时核对服务端身份。限制消息大小、结果数、并发、超时和取消。
- 查询、状态与管理权限分开；普通客户端不能修改任意输出路径、执行 SQL、运行命令、读正文、写源文件或更改 USN Journal。重建/暂停等控制必须是授权主体的固定请求，限流并记录结果；安装/升级走独立提权入口。
- 首版按调用者 Windows 身份过滤可见名称/路径。结果在服务端按调用者权限验证，无法确认则不返回；计数/分页不泄漏被过滤条目。不得将 SYSTEM 采集的全盘数据库直接交给普通用户。明确不依赖“只有我们的 UI 会连接”作为安全保证。
- 索引权限不等于文件操作授权。搜索候选返回桌面后，打开正文、移动、删除等继续走现有 Scope、文件身份复核、确认与取消机制。收紧权限/注销后失效相应会话与访问缓存。

桌面接入细化：用户启用全盘名称搜索后，名称发现按调用者操作系统权限覆盖受支持卷，不再以 `Scope.read` 的默认常用目录作为全盘索引覆盖边界；这是已批准的名称发现范围。`Scope` 仍约束后续详情读取、打开和写操作，不自动增加读取/写入目录或改变现有访问模式。设置和候选操作应解释两者关系；配置收紧后清空旧候选/模型执行上下文，新的搜索也必须重新核验身份。旧目录索引和受控现场搜索保留兼容，但不能标作全盘结果。

权限依据：[命名管道安全](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)、[服务访问权限](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights)、[LocalSystem 权限](https://learn.microsoft.com/en-us/windows/win32/services/localsystem-account)。具体权限裁减和结果过滤性能必须实测。

## 建库、更新与恢复

1. 自动发现在线固定 NTFS 卷，按卷 GUID 和文件系统身份管理；盘符只作为展示/路径映射。卷下线标记不可用，重新挂载核对身份。
2. 首次记录日志 ID/USN，完整枚举 MFT，在未发布的新代次中建库；补读枚举期间的变化，索引和检查点事务提交后再发布。
3. 补齐缺失父链；区分不可见、系统元数据、已删除和确实未知，不猜测路径。硬链接维护多个名称，变化时按文件身份重新协调链接集合。
4. 后台持续分批读取 USN；空闲采用等待/退避，不忙轮询，不按五分钟全盘重扫。自身数据库写入不成为反复刷新自身索引的循环。
5. 服务重启从持久检查点续读；日志 ID 改变、游标过期、未知版本、磁盘满或事务失败明确进入重建/降级/错误状态。日志缺失时不静默创建/调整 Journal；展示不可用原因并提供兼容选择。
6. 旧索引可继续用于标明“待更新”的搜索，新代次完成才替换。候选在实际操作前重新核验；不能把陈旧/局部结果标成完整实时结果。

卷状态：发现 → 建库 → 追赶 → 就绪；另外包含暂停、离线、需重建、覆盖不完整、不支持、错误。最后刷新时间、索引代次和覆盖说明是返回协议的一部分。

检索先用持久数据库和可替换的名称查询索引；以实测选择预归一化名称、候选加速结构或内存辅助索引，不预先承诺数据库全表扫描足够快。按页返回、不传全盘记录；禁止为了找无命中结果而退回整盘递归扫描。正文/时间/大小等不支持的筛选明确进入受控补充查询，不静默丢弃条件。
