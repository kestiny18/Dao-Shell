## 1. 产品目标与范围

在现有桌面会话里，用自然语言查看电脑事实并追问。回答简短，事实可展开核对，用户不需要理解进程采样或工具名称。Windows 普通用户权限是本期支持环境。

本期提供六类问题：CPU/内存与排行、磁盘空间、网络接口流量、运行进程/可确认运行应用、已登记安装应用、电脑配置。支持按已有事实解释资源压力。网络主动探测、持续监控、GPU 利用率、磁盘 I/O、启动/关闭/结束/安装应用不属于本期。已有 UI 动作不扩大到模型工具。

配置中的显卡型号可以读取，GPU 利用率属于后续能力。磁盘查询回答卷容量与空间，不将卷容量相加当物理硬盘容量，也不扫描目录分析空间归属。

## 3. 用户交互

### 3.1 入口

- 保留概览与现有会话标签；输入提示改为“查找文件，或询问电脑状态”。中英文各自提供正式文案键。
- 空会话给少量示例：“内存谁占得最多”“C 盘还剩多少”“正在运行哪些程序”。示例只填入/提交用户请求，不预采集数据。
- 正常回答结构：一句结论、少量关键指标、必要局限。观测卡承载来源、时间与详细列表；不向用户输出原始 JSON。
- 查询中显示“正在采样 CPU 和内存”等状态，可取消。结果已返回但模型失败时，仍显示本地事实及解释失败信息。

示意（虚构数据）：

```text
用户：内存是谁占得最多？
DAO：本次采样内存使用 22.7 / 31.7 GiB；列出的进程中 Chrome 占用最多。
     这只是进程内存口径，不能解释全部系统内存。

[CPU/内存观测 · 14:32:08 · 窗口 0.7 秒]
 内存 22.7 / 31.7 GiB    CPU 18%
 [内存排行] [CPU 排行] [重新查询]

用户：CPU 呢？
DAO：在刚才 14:32:08 的同次采样中……
```

### 3.2 观测卡

按工具提供资源、进程、网络、应用、配置五种只读卡。资源卡同时支持 CPU/内存排行；分页和本地查看详情不触发模型调用。默认列表 10 条，单页最多 50 条。

- 卡上的时间始终可见；历史恢复显示文本回执及原时间，不重新执行工具。
- “重新查询”由本地固定能力请求重做该卡参数，生成新卡；此操作不必请求模型解释。需要解释时用户继续提问。
- 卡不带运行、关闭、结束、卸载按钮；不附上现有概览的 action_id/termination_ref。
- 观测事件和最终 Reply 都携带 request_id/observation_id；前端按观测 ID 去重，并归入发起会话。切换标签不会写入另一个会话。
- 应用/进程/文件的“第几个”不能共享编号。含糊的“第二个”存在多种候选时追问；“上面内存排行第二个”绑定该观测内的行。

### 3.3 模型不可用

- 无模型时输入区域明确说明自然语言需要连接模型，同时保留“文件名搜索”和“查看电脑状态”两个显式本地入口。
- 本地电脑状态入口提供这五类查询，不引入新的自由文本意图分类器。
- 请求模型失败且尚未执行工具：不自动拿整句话搜索文件，显示重试及上述两个本地入口；文件名搜索仍可显式执行。
- 已有工具结果时保留结果，模型错误不抹掉事实，也不转为文件搜索。

这会调整当前聊天自动降级行为；作为本期有意变更记录并测试，避免“为什么网络慢”变成全盘文件检索。

## 4. 信息共享与隐私

本地查看继续无需模型。新增桌面配置 `computer_query_sharing`，值为 `ask/enabled/disabled`，旧配置缺字段按 ask 处理，与文件访问范围独立。

- 首次会话准备使用电脑工具时，显示一次本地说明：“查询结果中的系统配置、资源指标、程序名称/版本等可能发送给当前选择的模型；不发送文件正文、命令行或环境变量。”提供“允许并记住”和“暂不启用”。后者保存 disabled，可在设置开启。
- 用户尚未选择时不采集/发送电脑事实；不阻塞普通文件对话。模型可先返回无事实的 `permission_required`；由前端固定卡提示，不由模型文字变更设置。用户启用后点击重试当前请求，不静默自动重放。
- 开启后按请求查询无需重复确认。设置中列出共享字段，并显示实际模型连接；变更模型/连接时遵循已有保存后清空执行上下文机制，说明该开关适用于之后选择的模型。
- 关闭时清空内存中的模型对话和电脑观测引用；不继续从旧上下文带出事实。已经发送的数据无法撤回，已有本地可见历史保留。
- 概览“让模型解释”也经过同一策略；明确的本地启用选择可以同时完成本次解释的授权，不保留绕过开关的发送路径。

数据投影分两份：`LocalObservation` 为本地 UI 所需事实，`ModelObservation` 是经过白名单筛选和截断的投影。运行时完成投影后才给 Dialogue；系统提示不能承担过滤职责。

| 数据 | 可发送给模型 | 仅本地/不采集 |
| --- | --- | --- |
| 资源 | CPU 整机百分比、GiB/MiB、卷盘符与空间、Top N 程序名和占用 | 默认不发送卷自定义标签、用户目录 |
| 进程 | 会话行引用、进程名、占用、观测时间 | PID 可本地显示；映像路径仅用于本地匹配，命令行/环境变量不采集 |
| 网络 | “接口 1”等会话标签、是否配置 IP、收发速率 | 真实接口名可本地显示，IP/MAC、主机名不发送 |
| 应用 | 筛选页内的名称、版本、发布者、估算大小、运行证据状态 | 注册表原值、完整路径、图标与动作引用不发送 |
| 配置 | 系统版本、CPU/显卡型号、内存、架构、运行时长 | 主机名、用户名、序列号、设备唯一标识不发送 |

所有外部来源字符串视为不可信数据，限制长度、清除控制字符、以文本渲染；应用名里的指令不能扩大工具与权限。

## 5. 工具契约

保留三个桌面文件工具，新增/开放以下五个电脑工具。能力目录声明 `name/schema/desktop_policy/read_only`，桌面执行边界持有本地 Policy；既按策略生成 schema，也在 Runtime 执行前检查。直接调用与模型伪造工具名均不能绕过。

所有工具 deny_unknown_fields；名称筛选最长 128 字符，普通大小写不敏感子串，不执行正则/通配脚本。分页 limit 默认 10、范围 1–50，cursor 只能由本地生成。

| 工具 | 桌面参数建议 | 返回内容 |
| --- | --- | --- |
| `resource_snapshot` | `sections: [cpu,memory,disks]` 默认全选；`sample_ms` 默认 700、500–5000；`limit`；可选 `observation_id` | 所选整机指标、请求 CPU/内存时的同窗双榜、采样口径 |
| `process_list` | `filter`、`sort: cpu/memory/name`、`limit`、`cursor`、`sample_ms`、`observation_id` | 进程页、筛选匹配数、覆盖状态 |
| `network_snapshot` | `sample_ms` 默认 700、500–5000；`observation_id` | 接口标签、IP 配置存在性、收发 B/s |
| `app_list` | `name`、`publisher`、`view: installed/running` 默认 installed；`limit`、`cursor`、`refresh`、`observation_id` | 登记应用页；running 只返回有可靠证据的匹配项 |
| `computer_profile` | `refresh`、`observation_id` | 已有配置字段，加架构与新读取的运行时长 |

`sections` 省略保持资源组合查询；仅 disks 时不等待 CPU 采样。核心 Request 可加兼容字段，但现有 CLI 参数默认值与结构通过适配器保留。两端都使用相同的度量和投影逻辑，不要求同一天全面升级 CLI 输出信封。

`observation_id` 指定时只读取当前会话已有观测/本地过滤，绝不静默采新样本；过期返回 `observation_expired`。与要求 refresh 或新 sample_ms 冲突时返回 invalid_arguments。cursor 自带观测、筛选和排序绑定，续页不能换条件；换条件必须重新第一页查询。

运行应用：沿用唯一可执行路径关联；不按 basename 模糊合并，不声称列全可见窗口应用。多进程可列出匹配实例数；本期不汇总可能重复计算的内存占用，不把登记清单缺失当“未安装”，不把未匹配当“未运行”。

### 5.1 通用结果

```json
{
  "schema_version": 1,
  "observation_id": "opaque-session-local-id",
  "kind": "resources",
  "status": "ok",
  "observed_at": "2026-10-20T14:32:08+08:00",
  "sample_window": {"started_at": "...", "ended_at": "...", "elapsed_ms": 704},
  "source": "local_windows",
  "coverage": {"state": "partial", "reasons": ["process_access_denied"]},
  "cached": false,
  "limits": ["short_sample_not_root_cause"],
  "data": {},
  "page": {"returned": 10, "matched": 24, "next_cursor": "opaque"}

```

示例仅展示结构。`sample_window/page` 不适用时为 null；度量字段未知为 null，不能用 0 或空数组冒充。status 为 ok/partial/error/cancelled；coverage 是提供者限定范围内的覆盖，不能据此称全机完整。模型投影另含本地格式化 `facts_for_explanation`，统一单位与精度，模型引用而非重算。

稳定错误码：permission_required、permission_denied、unsupported、invalid_arguments、access_denied、timeout、cancelled、observation_expired、internal_error。用户提示双语本地化，不直接展示内部路径或底层错误堆栈。

## 6. 采集、缓存与追问

### 6.1 一次采样是什么

- 资源观测先采 CPU/进程基线，再等待规定窗口并取终值；双榜来自相同进程集合，沿用已验证的整机 CPU 口径。
- 内存是终点瞬时值，CPU 是窗口平均，磁盘是读取时点值；这些区别写入 metric metadata，不能都称“同一时刻瞬时值”。
- 网络速率用接口计数差/实际单调时钟间隔；接口消失、新增、计数回退标未知或部分，不给负速率。
- 多工具组合不保证完全同时；比较跨域事实时分别标时间。不为支持所有指标同窗增加新调度层。
- 只问 CPU/内存不枚举注册应用；只问安装应用不做 CPU 等待；只有 running 视图才补进程映像匹配。

### 6.2 生命周期

- 实时问题如“现在/重新看看”采新样本；“刚才那个/CPU 呢”优先引用兼容旧观测并明确其时间。本轮同一资源观测可以多次本地筛选，无需再采样。
- 会话观测库最多 12 组、总计不超过 8 MiB，10 分钟过期；先淘汰最旧。每组进程最多保存 2,048 行用于分页，超过标 partial，不持久化全机进程库。
- 应用静态目录缓存建议 60 秒，配置资料 5 分钟；均按实际采集时间显示。running 状态与运行时长不沿用静态缓存。刷新失败不能把旧值标成新值。
- 查询采集软预算 10 秒（含采样等待），在可取消循环和 provider 阶段边界检查；同步 OS 调用可能延迟返回，不承诺可硬中断，超时后迟到结果不得写回已结束请求。
- 保留现有全局请求准入，不并行跑多个高成本采集；取消阻止后续工具/解释请求，已完成卡可以保留并标完成时间。
- 单次模型工具投影上限建议 32 KiB，总工具调用沿用现有每轮 12 次上限。截断按字段/条目发生并给标记，不截断 JSON 字节。应用枚举保留现有安全上限。

内存上限和时间是实施初始参数，必须用受控大清单验证可用性；达到上限报告范围不足，不通过持续翻页绕开采集预算。

### 6.3 持久化

沿用工作区已有 receipt 文本：保存可见精简指标、原观测时间、范围说明。会话重启后详细卡与分页引用失效，历史注明“历史观测，需要重新查询”。不保存原始工具 JSON、图标、完整进程/应用库或可执行引用。

历史文本包含用户当时看到的程序名/指标，这是现有可见历史的一部分；共享开关关闭不会自动删除历史。删除会话遵循现有删除行为。

## 7. 组件与数据流

```text
用户消息
  → Bridge 请求准入（会话/请求绑定）
  → Dialogue（可用工具集与当前共享策略）
  → Runtime：策略检查、严格参数校验
  → resources / computer / profile 按需采集
  → LocalObservation 入会话观测库
      ├─ result 事件 → 本地观测卡（request_id 去重/归属）
      └─ ModelObservation 白名单投影 → 模型简洁回答
  → Reply 补发本轮观测摘要（防止事件遗漏）
```

建议新增 `src/observation.rs` 保存公共类型、会话缓存与投影；保留 `computer.rs`，仅把网络/应用实现提为子模块。不要增加统一 provider 插件注册中心；仅在需要模拟采集边界时用小接口或测试注入。

Reply 兼容保留 `items/search_receipt`，新增 `observations`（缺失默认空）；前端不再由 file items 是否为空判断有没有结果。重置会话同时清除电脑观测、模型上下文与旧文件候选；普通电脑查询不清空文件候选，普通文件查询不覆盖电脑观测。

`ExplainComputer` 经白名单投影与共享策略；沿用概览原始时间，不假装是刚采集。概览、聊天可共享短期静态采集缓存，但不共享会话行引用，也不触碰现有应用动作目录。

首批固定问题：

| 类别 | 问题 A | 问题 B |
| --- | --- | --- |
| 资源 | 现在 CPU 使用率多少？ | 内存谁占得最多？ |
| 磁盘 | C 盘还剩多少？ | 哪个盘剩余空间最少？ |

| 应用 | 装了哪些 Python 版本？ | 能确认哪些应用在运行？ |
