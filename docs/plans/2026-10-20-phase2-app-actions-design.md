## 1. 本期目标

完成“查询 → 识别具体对象 → 本地确认 → 执行 → 核验回执”闭环，先交付普通权限下的有限应用操作。

| 用户意图 | 本期行为 | 不能声称的结果 |
| --- | --- | --- |
| 打开/运行某个应用 | 从受支持的本地开始菜单入口启动 | 创建进程不等于主窗口出现或应用可用 |
| 关闭某个应用 | 向已确认实例的明确窗口集合请求正常关闭 | 消息已发送不等于已保存、窗口已关闭或进程已退出 |
| 强制结束某个进程/实例 | 对经核验的特定当前用户进程调用结束并观察退出 | 未观察到退出不能报已结束 |

“停止应用”有歧义时优先呈现正常关闭；没有窗口、无法正常关闭或超时时，说明原因并让用户另选强制结束。不会自动升级为强杀。“占用太高，怎么办”只查询和解释，不默认准备结束操作。

范围：Windows 普通用户桌面程序。模型本期不能请求管理员启动、任意命令行/启动参数、URI、服务操作、安装卸载、批量跨应用结束、杀进程树或后台自主优化。Store/便携程序发现及专有退出协议不扩展。

“重启应用”不是原子能力：本期可引导先关闭，再由用户发起启动；前一步未知时不串行猜测执行。不引入复合计划自动执行器。

## 2. 当前实现及需要补齐的地方

- 第一期 `observation::Store` 保存有界观测与行引用，模型投影刻意排除 PID、完整路径、原生身份、动作引用。这些观测是事实，不是授权或操作句柄。
- 桌面 `app_actions.rs` 已有开始菜单解析、入口/EXE 文件身份固定以及本地 run/admin/location/uninstall 分发；目录 refresh 会更换引用，不适合作为跨会话模型对象库直接使用。
- 桌面 `process_actions.rs` 已有精确实例集合、90 秒一次性确认、逐项结果；底层 `process_control` 已检查 PID、创建时间、映像、用户和会话，并通过同一个进程 handle 核验和结束。
- `RequestControl` 与 Bridge 已有请求归属、取消、确认等待、配置变化失效和全局请求互斥，可复用。
- 目前没有正常窗口关闭语义，也没有模型应用操作工具、可复用的会话动作状态或桌面应用动作持久回执。

本期收拢已有能力；不另建通用电脑管理服务、不把管理员索引服务用于应用控制、不重写文件移动日志模型。

## 3. 用户流程

### 3.1 启动

1. 用户：“打开某应用。”模型查询操作目标；本地枚举支持的开始菜单入口，按显示名称筛选。
2. 唯一候选时可请求准备启动；多个候选先让用户按名称、发布者/版本和本地入口位置消歧。无法核实的字段不补猜。
3. 显示本地确认卡：应用名、实际 EXE/入口位置、普通权限、无自定义参数；按钮“启动”“取消”。完整路径只在本地显示。
4. 确认后复核入口和目标身份，执行一次，先给本地回执再给模型摘要。
5. 若已观察到相同应用在运行，确认卡说明本次仍会请求启动，可能激活已有实例或产生新实例；用户选择后才执行。模型不自动重复启动。

没有符合规则的入口时返回 launch_unavailable，不扫描全盘猜 EXE、不退回 Shell/PowerShell、不将 DisplayIcon/UninstallString 当启动命令。

### 3.2 正常关闭

1. 用户：“关闭这个应用。”从当前操作目标中确定实例；第一期观测可用作查询线索，不能直接执行。
2. 多实例时先选择；默认一个具体实例。对该实例发现可关闭的顶层主窗口集合，展示窗口数量和本地窗口区分信息。
3. 本地确认卡说明：“向此实例的这些窗口请求正常关闭；应用可能提示保存，也可能继续在后台运行。”按钮“请求关闭”“取消”。
4. 执行后短时观察窗口与进程状态，分别报告。仍运行或窗口仍在时显示“尚未观察到完成；请检查应用是否提示保存”，不推断一定存在保存对话框。
5. 可点“核对结果”，只读检查原目标；若用户要强制结束，重新准备另一张强制结束卡并确认。

窗口标题可能包含文档或聊天内容，仅用于本地区分，不自动发送给模型、写入持久日志。不能明确区分主窗口/对话框、跨用户或高权限窗口时不发送关闭消息。无受支持窗口时返回 no_closeable_window。

### 3.3 强制结束

1. 用户明确要求强制结束；工具目标必须是已观察并重新核验的进程实例引用。
2. 确认卡列进程名称、本地 PID、实例创建时间、应用关联依据，并醒目提示可能丢失未保存内容。按钮“强制结束此实例”“取消”。
3. 执行只针对该实例，不结束子进程、不加入同名新实例、不按名字重查替代目标。
4. 观察原进程 handle 的退出状态；已先退出返回 already_exited，不把之后复用 PID 的进程当目标。

首版动作工具一次处理一个进程实例；一个实例的多个正常关闭窗口必须一次完整列入确认。多实例应用先让用户选具体实例，不承诺“关闭整个 Chrome”能覆盖所有浏览器子进程。保留现有概览已明确支持的单应用冻结实例集合，不新增跨应用批量接口。

## 4. 目标模型与查询工具

### 4.1 观测引用和操作引用分离

新增会话内 `ActionTargetStore`，只存普通用户可用的精确目标，不往第一期原始 JSON 塞入授权信息：

- `LaunchTarget`：入口路径和 FileIdentity、EXE 路径和 FileIdentity、已解析入口属性、采集时间。
- `ProcessTarget`：PID、精确创建时间、映像、owner/session 及必要的保护状态；原生字段仅本地保存。
- `CloseTarget`：ProcessTarget 加本次明确窗口集合；HWND 只在本地，不能独立当身份。
- 对模型仅返回不透明 target_ref、显示名称、候选类别、可准备动作及不可用原因；引用不是确认凭证。

target_ref 默认有效期 2 分钟，每会话最多 256 个；准备时重新捕获并冻结，确认另有 90 秒期限。第一期 10 分钟观测的生命周期不延长操作目标有效期。

第一期旧观测行可能只含秒级开始时间，不能可靠升级为精确实例。根据旧行查询时必须重新发现并呈现操作候选；无法证明为同一实例时返回 needs_reselection，让用户选择新候选，不静默把旧行绑定到现在同名程序。新操作发现通过原生精确身份核验，再用于动作。

### 4.2 新增四个模型工具

| 工具 | 参数 | 语义 |
| --- | --- | --- |
| `app_targets` | `kind: launch/close/terminate`；`query` 或 `observation_id + row_ref` 二选一；有界 limit/cursor | 只读发现和消歧；返回目标及 supported/reason |
| `app_launch` | `target_ref` | 准备普通权限启动，等待本地确认并返回真实回执 |
| `app_close` | `target_ref` | 准备正常关闭窗口集合，等待本地确认并观察 |
| `process_terminate` | `target_ref` | 准备强制结束单个精确实例，等待本地确认并观察 |

目标引用按动作类型绑定，launch 引用不能拿去 terminate。所有请求 deny_unknown_fields；工具不接受 path、pid、command、args、admin、confirmed 或 confirmation_id。query 仅作名称子串筛选，不成为执行参数；cursor 绑定筛选和会话且不能切换 kind。

`app_targets(kind=launch)` 复用保守入口解析；即便注册清单未完整登记，开始菜单存在受支持入口也可作为明确来源候选。不能为了扩大可用率自动放开入口限制。

`kind=close/terminate` 只发现当前用户、当前交互会话且符合保护规则的实例，查询失败说明覆盖局限。查找程序时不依赖“存在启动入口”才允许核验进程，但应用归属不可靠时只称具体进程。

动作工具在本轮运行中等待本地确认，最终返回本地结果；不提供给模型独立 confirm/execute 工具。确认卡是过程事件，绝不能提前输出“已启动/已关闭”。

## 5. 确认、取消与会话归属

不可变 `ActionPlan` 至少记录：operation_id、session_id、execution_id、action_kind、目标精确身份/窗口集合、配置修订、风险、created_at/deadline。用户在卡内换实例必须生成新计划和新确认，旧确认立即作废。

- 默认拒绝：没有本地确认、等待超时、前端断开、取消均不派发。
- 复用 RequestControl 的一次性 token，由 Bridge 校验会话、execution_id、配置修订和计划后消费。模型输出“用户同意”不影响此状态。
- 同一桌面进程保留全局互斥；等待确认期间不并行采集/刷新或开始另一动作。用户可以取消待确认再做其他任务。
- 切到另一标签不会把确认迁到新会话；用户可回原会话处理。关闭发起标签、删除会话、重置、关闭窗口均取消未执行计划。配置保存先遵循既有忙状态约束，外部配置变化仍导致旧确认失效。
- 确认消费后再核验目标；发生替换、权限变化、窗口集合变化时拒绝旧方案，不自动修改确认范围。
- 派发前取消保证不执行；派发后取消只停止尚未开始步骤/观察，不能撤回已启动程序或已发送消息，更不能声称“已取消所以未发生”。
- 同一用户轮最多一个改变电脑状态的计划；取消、拒绝、超时、结果未知后禁止模型再准备同类或替代动作。返回用户等待新指令，防止反复弹卡或换工具绕过拒绝。

重复模型调用在同一轮复用已产生回执；不因为新的 tool_call_id 就再次执行。跨轮新请求可产生新计划，但未知结果必须先核对，不自动重放。

电脑共享开关仍控制模型能看到的应用/进程事实及动作摘要；关闭时模型查询/动作工具拒绝，不触发采集或执行。没有额外“永久允许模型任意操作”开关；每次本地动作确认就是授权边界。现有本地 UI 动作仍可在不共享事实时使用。

## 6. Windows 执行设计

### 6.1 启动

复用现有开始菜单入口解析和 pin：本机固定盘、明确 EXE、无自定义参数/工作目录、不跟随重解析点、非已拦截解释器及安装维护入口。用户选择的路径不等于软件可信认证；本期不新增二进制信誉或签名平台。

建议模型启动使用普通用户 `CreateProcessW` 路径：显式绝对 lpApplicationName，程序自行生成正确引用的 argv[0]，无附加参数，禁止继承句柄；工作目录固定为已核验 EXE 的父目录并在本地预览中说明，不取模型/注册表值，不继承 Dao-Shell 的凭据环境。子进程环境仅由本机标准用户环境构造，排除配置的 API key 环境变量和本产品的测试/配置注入变量，不能直接照搬整个父进程环境。

遇到需要提升/不支持的启动语义返回 elevation_required/launch_unavailable，不回退 runas 或 Shell。若 Dao-Shell 本身被提升运行，新模型动作拒绝执行并提示用普通权限重新打开；不能将“未指定 runas”当作保证普通权限。

创建后保留返回进程 handle，以 3 秒观察预算记录 process_created、仍运行/已退出/退出码（有证据时）；已有单实例程序可能由短命启动器唤起，不能由启动器退出推断主应用失败，也不能把别处同名窗口当本次新启动证据。窗口出现证据可以补充，但始终与进程创建分开报告。

普通 Shell 启动 API 的 hProcess 在部分情形不会返回，而且错误 UI 标志不抑制安全提示；因此不直接用现有 Shell 分发加“启动成功”文案替代本期设计。[Microsoft SHELLEXECUTEINFOW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow)、[CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)。

### 6.2 正常关闭

正常关闭新增 provider。通过窗口所属 PID 加精确进程身份核验，仅枚举确认中的当前用户可支持主窗口，不广播、不遍历文档正文，不关闭保存对话框。

首选有界地投递 WM_CLOSE（PostMessageW）并观察，不同步无限等待目标窗口线程；每个消息发送前复核窗口归属/实例身份。投递返回只证明入队，不证明窗口处理完成；UIPI/权限拒绝如实返回，不提权重试。WM_CLOSE 允许应用选择保存、拒绝或忽略，Dao-Shell 不代替应用决定。[Microsoft 窗口关闭说明](https://learn.microsoft.com/en-us/windows/win32/learnwin32/closing-the-window)、[PostMessageW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)。

核验 HWND 与发送之间没有现成的“永久窗口身份”保证。T0 必须用受控程序验证句柄复用、并发销毁/创建和消息发送竞态，记录可保证的边界；不能把 IsWindow 一次检查当原子身份核验。若实现无法将行为限制在所确认对象，正常关闭保持不可用，修正方案后再开放，不用真实办公应用承担试验。

首版观察预算最多 3 秒，按窗口/实例报告：close_requested、window_closed、process_exited、still_running、unknown。应用窗口消失但进程在后台时明确区分；尚未完成不等于失败，更不证明可安全强制结束。后续“核对结果”仅复核原对象，不重复投递消息。

### 6.3 强制结束

复用 `process_control::terminate` 的同 handle 身份核验和 TerminateProcess 机制，保留原有系统/关键进程、自身、WebView、索引 worker、explorer 等保护规则。未知身份、跨用户/跨会话或拒绝访问均停止，不尝试管理员权限。

底层现有 50ms 等待不足以保证看见最终退出，上层可在不阻塞 UI 的 3 秒预算内继续只读等待原 handle。超时记录 termination_requested/still_running，之后可核对，不再调用一次 TerminateProcess。PID 查询不到不能单独作为原目标已退出的证据。

## 7. 回执、幂等与崩溃

分开保存操作生命周期与观察事实，不设计一个模糊 success 布尔值：

- lifecycle：awaiting_confirmation、rejected、expired、invalidated、dispatching、dispatched、failed_before_dispatch、unknown。
- evidence：进程是否创建、消息是否入队、哪些窗口消失、原进程是否退出、观察时间、每项错误码及未开始项。
- 用户摘要按证据生成：如“已请求关闭；窗口仍在，进程尚未退出”，而不是“关闭失败/关闭成功”二选一。

新增最小持久动作回执，复用 SQLite 依赖及已有存储安全约束，使用独立 app_actions 表/版本，不把应用动作伪装成文件 Operation。存储位置沿桌面配置数据目录隔离，不能持有 CLI 文件移动库锁阻塞其使用。

确认前计划只在内存；确认并核验后，先持久记录 dispatching，再调用 OS；记录不可写则不执行。派发后保存事实，若写回失败保留本地警告，不自动补发。重启时 dispatching/观察未完成项恢复为 unknown，确认卡不恢复且绝不重放。OS 副作用和数据库不能组成原子事务，本期不承诺跨崩溃 exactly-once。

回执仅本地保存动作、时间、显示名称、必要原生核验身份/范围、状态，不保存窗口标题、正文、凭据或整个应用/进程目录；模型只接收裁剪后的摘要。建议已完成回执保留 7 天并提供清理；unknown 不自动当完成清除，明确列出“待核对”。持久化内容本身不授予恢复后继续动作的权力。

“核对结果”是固定本地只读入口，根据本次 operation_id 及仍可验证的原身份更新证据；无可靠证据保持 unknown。未知后新发现同名应用不能反向证明上次动作是否发生。不同 Dao-Shell 进程/外部任务可独立改变电脑状态，本期进程内互斥不被描述为全系统动作锁。

## 8. 架构与迁移

```text
Dialogue / 本地操作 UI
   → Capability policy + 当前轮动作限制
   → 会话 ActionTargetStore（发现与消歧）
   → ApplicationActions.prepare（冻结 ActionPlan）
   → Interaction.confirm_app_action
   → Bridge / RequestControl（本地一次确认、归属、取消）
   → 再核验 → 最小回执 dispatching → Windows provider
   → 观察与逐项回执 → 本地 UI / 模型裁剪摘要
```

新增核心 `application_actions`，只包含目标、计划、执行状态与回执；Windows 模块承接开始菜单解析/启动/窗口消息，继续复用 `process_control`。`Interaction` 增加应用确认方法，CLI 默认拒绝，CLI 本期不开放新动作工具。

桌面 `app_actions/process_actions` 逐步变薄，保留原有 explicit UI 的 admin/location/uninstall 行为独立分支。普通启动、身份核验、保护规则和回执格式尽可能共用；不能为统一接口悄悄把管理员启动/卸载导出给模型。

第一期能力目录新增四个明确工具条目，执行端同样检查；不提供 `execute_action(action: string)` 总入口。观测卡只在已识别可操作目标后提供准备入口，未核验行显示不可操作原因，不能因为在排行中出现就默认可结束。

事件建议：action_prepared（本地完整预览）、confirmation_closed、action_receipt。带 session_id、execution_id、operation_id；确认 token 仅在本地事件与回答通道出现，模型回执不含 token/原生路径。最终 Reply 补发回执摘要，前端按 operation_id 去重。可见历史保留动作摘要和核验时间，不能恢复可点击旧确认。

## 9. 实施任务与验收

### T0 — 原生动作可行性与边界试验
Implementation: PLANNED

使用专用测试程序模拟多窗口、保存提示、忽略关闭、短命启动器、普通/提升需求及并发窗口重建。验证普通权限启动环境、pin 期间目标替换拒绝、关闭消息身份竞态和退出观察。输出事实及未支持场景；此任务不要求新增产品框架。

### T1 — 核心目标与计划
Implementation: PLANNED

实现操作目标发现、独立引用、不可变计划与严格参数；旧观测只作线索。验证伪造/过期引用、跨会话、PID 复用、入口替换、重名/多入口、受保护/高权限目标、筛选与分页不会转绑对象。

### T2 — 启动闭环与最小回执
Implementation: PLANNED

交付普通权限启动、本地确认、派发前日志及结果摘要。覆盖 double click、重复 tool call、取消前/后、确认超时、提升要求、启动器转交、写盘失败与崩溃未知。为此阶段单独小步提交并交付受控原型。

### T3 — 正常关闭与强制结束
Implementation: PLANNED

两种动作分开实现并各自验证：保存提示不代点、窗口关闭不等于进程退出、确认集合变化拒绝、进程已退出/PID 复用不操作新进程、取消不撤回已发生结果、未知不重试。正常关闭能力必须满足 T0 所明确的安全边界。

### T4 — 桌面与模型协议回归
Implementation: PLANNED

中英确认卡、明确风险、实例选择、三种不同结果、核对入口、重启历史、共享关闭和本地功能；固定本机模型验证真实 UI 事件、令牌不泄漏、取消后不换工具再试。

回归第一期五查询与原有文件打开确认；同步核心/桌面测试、格式、Clippy 和必要 Debug 构建。外部 API/凭据不可用时不为了测试花费真实模型调用费用；真实模型理解效果单独记录模型版本和 NOT_VERIFIED。

首批自然语言场景：唯一应用启动；重名应用消歧；已运行应用再次启动；关闭单实例；多实例先选择；关闭后仍在运行；明确强制结束；进程已退出；“太卡了”不自动操作；用户取消后模型不得重复请求；共享关闭；“重启”不执行复合动作。

自测只操作专用测试应用、虚构文件和隔离配置，禁止实际结束工作机办公程序、真实浏览器或未保存文档。不同权限测试必须显式构造隔离环境，不为测试自动升级本体或服务。

## 10. 状态与下一步

当前为设计，未实现或测试正常关闭/新启动路径。只有 T0–T4 必要自测完成且无已知误目标路径，才可标本期 Implementation: READY；功能被阻塞时如实标对应任务，不将整期称完成。

独立测试、评审仍由用户触发。建议在实际日常程序试用前针对实例身份、确认归属、窗口消息竞态和崩溃未知做独立检查，本方案不自动派发角色。

建议实施顺序 T0 → T1 → T2 → T3 → T4。T2 和 T3 分别形成可验证的小步提交；当前设计不授权实施、真实应用操作或发布。
