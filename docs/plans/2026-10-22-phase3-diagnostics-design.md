## 1. 目标、依赖和交付边界

把“当前一个样本”扩展到“这一小段时间发生了什么”，给普通用户可核对的诊断证据。诊断回答必须区分观测、相关性和待验证假设；不能据此自动结束应用或修改系统。

第一期观测/共享策略已实现，第二期仅启动与明确实例强制结束可试用，正常关闭仍 BLOCKED。第三期只读工作不依赖正常关闭完成；Store/便携应用的启动扩展必须另外满足第二期目标身份和确认规则。不能通过本期的应用覆盖工作把正常关闭改标完成。

拆为三个可独立交付批次，但第三期整体只有必选项全部完成才标 READY：

| 批次 | 必选交付 | 完成条件 |
| --- | --- | --- |
| 3A：短时观测 | 30/60 秒 CPU、内存、网络序列；单次结束摘要；前后对比 | 有时间序列、可取消、无需常驻服务、不混用不同口径 |
| 3B：网络诊断 | 接口/路由/DNS 配置只读；明确目标的 DNS/TCP/HTTPS 分层探测 | 分层结果与原因，不以一次失败判断全机断网 |
| 3C：补充覆盖 | 进程 I/O、电源/电池；GPU/显存可用性；Store/便携应用发现；启动项只读 | 每项可用/不可用原因明确，有受支持环境证据 |

GPU、Store 启动等平台能力先做小实验。无法取得可靠数据时保留对应任务 BLOCKED/NOT_VERIFIED；只报告“不可用”不等于完成承诺的能力。不能偷偷把 3C 未完项变成可选项后宣布整期完成。

本期不做长期监控、告警、自动修复、抓包、浏览记录、窗口正文、全盘便携应用扫描。没有新的无人值守任务或后台 daemon。

## 2. 用户体验

### 2.1 短时观测

用户：“观察一分钟，看看卡顿时资源怎么变化。”

1. 显示观测卡，说明持续 60 秒、所选指标、是否共享给模型；未选择的指标不采集。
2. 点击开始或明确提出该只读观测后运行，展示剩余时间和本地趋势。无需每秒模型调用，不逐点上传。
3. 用户可以停止；完整和中止的观测均标实际时间范围，中止只总结已取得样本。
4. 完成后按共享策略发送有界摘要，回答峰值、均值、持续高占用时间与可靠匹配的进程贡献。样本不足时不输出趋势结论。
5. 图上空缺就是空缺，不能插值成平滑的“正常曲线”；峰值不自动等于根因。

“对比刚才”要求两个明确 observation_id，列出各自时间、长度、样本数和口径。应用/设备身份变化时不把两条同名曲线当成同一对象。

### 2.2 网络诊断

“网络为什么慢”先读取本地接口、配置和已有速率。需要外部探测时展示实际目标、协议和会发送少量请求；用户选择后才发起。

只读配置不代表连通；DNS 成功不代表 TCP 成功；TCP 成功不代表 HTTPS/业务成功。HTTP 认证、重定向、证书错误、代理策略、VPN 和服务器拒绝分开报告，不称为全机断网。

用户可输入自己想验证的公开域名，也可选经本地配置的局域网目标。没有全球默认测速站；不自动搜索附近设备或扫描端口。需要用户登录的网页只报告所见状态，不索取凭据。

## 3. 工具与数据契约

工具建议名称在实施时固定版本；所有参数严格校验，不接受 command、script 或任意 counter path。

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `resource_observe` | domains(cpu/memory/network/io/gpu/power)，duration_s=30/60，interval_ms=1000/2000，最多 5 个已发现进程引用 | 在本轮内运行，过程只发本地进度，结束返回 observation_id 与摘要 |
| `observation_compare` | left_id、right_id、metrics | 当前会话中兼容的两组观测对比，无新采集 |
| `network_diagnose` | mode=local/probe，已配置/新提交 endpoint_ref，checks=dns/tcp/https | 分层事实、各阶段耗时、目标范围和错误码 |
| `startup_list` | source=user/machine，filter、limit/cursor | 当前用户可读取的启动项、来源、状态可信度；不执行字符串 |

原有 `computer_profile/network_snapshot/app_list` 扩展带版本字段，不为每个新指标再增加工具。Store/便携应用仍由 app_list 返回带 source 的结果。

endpoint_ref 由本地目标卡生成，不允许模型拼接 URL 后直接访问。新域名/协议/端口/路径扩大都需要重新确认；允许的本地工具调用不能被模型当作长期扫描许可。

观测结构沿用第一期信封，新增 series、summary 和 metric_definitions：

- series：elapsed_ms、采集时间、值/unknown_reason；CPU 为区间平均，内存为点值，网络/I/O 为相邻计数差除实际时长。
- summary：有效点数、缺失数、min/max/time_weighted_mean、峰值时间、阈值与持续时间。阈值是产品显示规则，不是故障证明。
- metric_definitions：单位、整机/单核/进程口径、来源、计数器是否共享/重复归属、可比性。
- coverage：采集器失败、进程退出、接口变更、设备变化、时间漂移、采样被跳过分别记录。

模型先接收本地确定性计算的摘要和最多 20 个代表点；UI 保留完整有界序列。不得让模型自己从截断点重算精确统计。

## 4. 采集预算、并发与取消

- 首版每桌面进程同一时刻一项短时观测；保留现有全局请求准入。提示用户停止观测后才能执行其他动作，不顺手重构为多任务调度器。
- 时长 30/60 秒，间隔最少 1 秒，最多 61 个点/序列、5 个进程、8 个网络接口；超限选择筛选并标覆盖。
- 会话最多 4 组 series，独立总预算 8 MiB；与既有单样本缓存合计最多 16 MiB。系列 10 分钟过期，达到预算先淘汰最旧组，不能无限累计。
- 用单调时钟调度和计算速率；超时采样记 missed，不靠补跑把延迟点伪装为按时点；休眠/唤醒打断区间，不能把长空档算正常低占用。
- provider 每点软预算建议 500ms，慢字段在后续点跳过并标记。同步 Windows 调用不能承诺可硬中断；迟到点不回写到已取消请求。
- 停止只取消本次采集/后续解释；删除会话或退出不恢复采集。重启只保留用户可见的时间和摘要文本。
- API 费用只来自结束后的解释请求；本地曲线刷新不调用模型。模型不可用时完整本地观测仍可用。

## 5. 网络探测边界

每次探测最多 3 个明确目标，每目标每层最多 2 次，DNS/TCP/HTTPS 每次上限 3 秒，总墙钟软预算 20 秒。目标是端点可达性，不是带宽测速或持续 ping。

- 只允许 DNS 查询、指定端口 TCP 握手及无认证 HTTPS HEAD；不发送用户文件、不跟随任意链接、不带 Cookie/API key 或自定义请求头。405 等结果仅说明该端点不支持 HEAD。
- URL 禁止用户名密码、query/fragment，首版只接受主机名加根路径和明确端口。重定向默认不跟随，显示新目标；需要继续须确认新目标。
- 公网目标 DNS 解析至私网、loopback、link-local、保留地址时停止并标目标范围变化；如用户确实需局域网诊断，用单独确认的 local endpoint_ref。发起连接前再次核对解析范围，避免重绑定跨范围访问。
- DNS 检查使用所选系统路径；HTTPS 明确是否沿系统代理，返回代理是否生效。不能混用自定义 DNS 和代理绕行后称为系统网络结果。
- 不调用本机云元数据端点或本地管理接口作为“测速”；无用户选定局域网目标时不自动探测。
- 主机/IP/代理详情仅本地显示，发送模型默认使用“目标 1”“接口 1”及分层错误；用户自述文字本身可能含域名，应在共享说明中写清。

上述限制是待实现的固定 provider 行为，不通过提示词保证。只读采集、模型共享、主动联网三种授权分开，不因开启信息共享就自动探测外网。

## 6. 指标与应用覆盖方案

### 6.1 I/O、GPU、电源

进程 I/O 优先验证 GetProcessIoCounters 的普通权限可用性与计数差；其语义是进程全部 I/O，不能直接命名为“磁盘物理读写”。磁盘忙碌率/吞吐与进程 I/O 分开，不混合累加。API 依据：[Microsoft GetProcessIoCounters](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getprocessiocounters)。

GPU/显存先验证本地性能计数器候选，用明确适配器/引擎维度；不把多个 GPU engine 百分比简单求和当整机使用率，不把共享显存算专用显存。无法解析稳定实例身份或驱动不支持时标不可用，记录受支持环境而非盲目加后台服务。[Windows 性能计数器说明](https://learn.microsoft.com/windows/win32/perfctrs)。

电源读取 AC/电池存在性、电量及系统提供的剩余时间估计；台式机无电池为 not_applicable，估计时间未知不能报 0。默认不新增 WMI 常驻查询或厂商驱动。

### 6.2 应用与启动项

- Store：只查询当前用户可见的包身份/应用入口，不扫描包内容；把包、应用入口、进程映像三种对象区分，多个入口不能仅按显示名合并。
- 便携应用：只收集已授权目录中明确选择的 EXE 或既有开始菜单入口；不做全盘 EXE 扫描。用户登记仅授予发现，后续启动仍需确认和身份核验。
- 多入口：同名不同来源/版本可并存；unsupported duplicate 不得被静默过滤后挑出另一个有效入口。
- 新启动 provider（如 Store）先做只读映射及小实验；安全路径未验证则显示 launch_unavailable，不绕到任意 URI/命令参数。
- 启动项首批读取 Run/RunOnce 和 Startup 文件夹等明确来源；读取不到标 partial，注册字符串只显示，不展开执行、不把存在登记当 enabled 的充分证据。服务/任务计划不是本期启动项覆盖。

## 7. 架构改动

新增小模块 `diagnostics` 保存时间序列采样循环、摘要、比较；扩展现有 observation 类型但不为序列复制一套会话/权限系统。网络主动探测隔离为固定 provider，共享策略在模型投影前执行。

CPU/内存/进程/网络 collector 可复用现有数据来源；以开始/结束采样函数避免每秒重新扫描应用目录。仅对确有测试注入需要的边界引入小接口，不建设 provider 插件注册中心。

UI 增加序列卡/简单趋势图与网络分层卡：明确时间、缺失、范围、观察中/完成/已停止。事件继续带 session_id、execution_id、observation_id；新旧请求不能串写。卡片不带自动结束/安装/修复按钮；动作建议必须是下一条用户明确请求。

## 8. 实施任务与验收

| 任务 | 主要交付 | 必要自测 |
| --- | --- | --- |
| T0 数据可用性实验 | I/O/GPU/电源、Store/启动项 provider 的范围和错误矩阵 | 固定样本、普通用户实机只读检查，禁止提权补数据 |
| T1 30/60 秒观测 | 时间序列、预算、取消、缺失与摘要 | 虚拟时钟、计数回退、进程身份变化、休眠空档、内存上限 |
| T2 追问与比较卡 | 趋势、本地对比、结束后单次模型解释 | 相同/不同口径、样本不足、事件重复、跨会话/重启失效 |
| T3 网络分层探测 | 目标确认、范围约束、DNS/TCP/HTTPS结果 | 本机虚构服务器、超时/重定向/代理/重绑定/拒绝后无请求 |
| T4 补齐覆盖 | I/O/GPU/电源、Store/便携/启动项只读 | 来源消歧、无电池、驱动缺字段、注入字符串、不扫描未授权目录 |
| T5 交付 | 受影响 Rust/UI/协议测试、Debug 与证据 | 第一二期回归、固定本机模型真实界面试用、来源版本绑定 |

建议小步提交顺序 T0 → T1 → T2（3A交付）→ T3（3B交付）→ T4/T5（3C与整期交付）。不提供未经实测的日历工期。

固定场景至少覆盖：观察30秒并中止；60秒资源正常结束；模型断线本地曲线保留；前后比较口径变化；计数器复位；DNS失败但本地接口有IP；TCP成功HTTPS证书失败；公网端点转私网拒绝；无电池；GPU不可用；Store重名；启动字符串含指令。协议模拟不替代真实模型效果，未执行项保持 NOT_VERIFIED。

## 9. 完成、依赖和未验证项

所有必选项有证据且必要自测通过，才标第三期 READY。可提前交付 3A/3B 子范围，但保留整体状态与缺口。独立测试、评审按用户触发，不自动启动。

第二期正常关闭继续独立 BLOCKED；第三期不能通过它的不可用文案冲销该任务。第四期读取型软件发现可以并行设计，真实维护需自己的 provider 和隔离操作证据，不能用本期诊断结论代替维护授权。

本设计未测量时序开销、Windows/驱动兼容、系统代理差异或长期稳定性；参数为实施初始预算。设计完成不代表实现或验收完成。
