## 1. 目标和范围

从“诊断后给建议”延伸到“用户选定的一项维护动作，有具体方案、有本地确认、有结果核验”。保持单应用/单设置、单次明确请求，不做一键优化或定时批量维护。

| 批次 | 实现范围 | 用户示例 |
| --- | --- | --- |
| 4A 软件安装闭环 | 已配置 community 源、单包、固定版本/范围；已安装则不重复安装 | “看看 VLC 装没装，没有就安装” |
| 4B 更新与卸载 | 单个已可靠关联的软件更新或卸载，逐次确认 | “把选中的这个软件更新到这个版本” |
| 4C 启动项维护 | 当前用户 Startup 文件夹中受支持 .lnk 的禁用/恢复；其他来源只读或固定设置页引导 | “下次登录不要启动这个快捷方式” |
| 4D 有限网络维护 | 明确的本机 DNS 缓存清理；其他网络设置引导到固定系统页面 | “清理本机 DNS 缓存，再检查刚才的域名” |

安装是首个交付，复用 docs/MVP.md 的 A1 语义；更新、卸载、启动项和 DNS 每批有自己的完成条件，不作为安装的隐藏附带操作。四批都必选；未完成某批不能把整期标 READY。

不接入付费商店、账号购买、任意下载链接/本地manifest、安装器自定义参数、批量 update-all、远程脚本、注册表卸载字符串执行、驱动/系统更新、全局网络重置、服务/任务计划、自主重启或通用管理员命令。

## 2. 前置条件和第二期缺口

- 复用第二期本地确认、进程内准入、防重复和 unknown 回执；实施前核对日志恢复、模型投影和跨工具限制仍满足维护场景。
- 正常关闭仍 BLOCKED。安装器需要先关应用时，本期只提示用户自行关闭并再次检查，不能把强制结束当安装前置步骤自动执行。需要强制结束必须是另一个用户请求及另一份确认，不与安装串成一项。
- 第三期网络诊断可供前后对照；没有它时仍可安装，但不能将下载失败自动解释为“该修复网络”。
- 软件包 provider 的类型化发现、范围和安装后查证能力必须通过 T0；未通过阻塞软件写操作，不阻塞只读软件目录查询。

## 3. 软件查找、方案与确认

### 3.1 安装

1. 查询已安装状态和指定来源候选，呈现可靠匹配依据、软件ID、名称、发布者、版本及来源。
2. 已满足条件则说明现状，不重复安装或默认升级；未检测到但覆盖不足则 unknown，不能由“没搜到”直接执行安装。
3. 多候选或来源/用户级与机器级范围不明，先让用户选择；不能让模型猜最像的包ID。
4. 本地准备不可变方案：精确包/源/版本、架构、范围、是否需要权限、预计影响、协议及是否可能要求重启。下载大小未知写未知。
5. 本地一次确认后执行；Windows/安装器合法要求的提升或协议由人处理。不通过默认接受协议参数代替用户选择。
6. 完成后重新查询同一软件身份与版本/范围，再给结果。退出码仅为证据之一，程序可启动与功能正常另列未验证。

条件请求“没有则安装”仅在 absent_verified 且确认卡说明该判断的时间/范围时准备安装；执行前再查，状态变化则旧计划失效。

### 3.2 更新

固定现有安装身份、当前版本、目标版本、源和范围。目标版本 unavailable 不自动换 latest。版本比较由 provider 的版本语义决定，不能对所有产品使用字符串/semver大小比较。

提示安装器可能替换程序、改变配置或需要人工退出；未知保留未知。不默认卸载旧版，不静默改变安装范围，不为更新自动调用强制结束。没有可靠回滚路径时明确“不提供自动回滚”，不能称为可逆操作。

### 3.3 卸载

确认卡显示具体安装实例/版本/范围和可能影响用户配置的局限。只支持 provider 能明确关联并提供卸载能力的对象；注册表字符串、同名进程或软件目录都不是卸载凭证。

卸载后重新查询该实例；其他版本还在不等于本次失败，清单暂时消失也不能单独证明完全卸载。用户数据、残留文件不扫描或自动删除。安装器询问保留/删除数据时交给用户，不代选。

## 4. 软件 provider 选择

先做 WinGet 类型化 COM/部署 API 实验，关注本机版本、激活条件、来源协议、安装身份关联、进度、取消和错误语义；不能把源码 master 的接口当作本机已支持的接口。记录实际测试接口及最低可用版本，不擅自安装/升级 WinGet 来绕过缺失。

COM 不可用时可以验证固定 CLI adapter，但必须同时有可靠的结构化发现/已安装状态来源；不解析本地化表格当稳定协议。两条路径都不能满足时保持只读、显示 provider_unavailable，不能放开通用Shell。

CLI 如获验证：只由程序生成固定 allowlist 动词及精确 ID/source/version/scope，显式可执行路径、独立 argv、不经 Shell；模型不能增加 flags、headers、override、manifest 或改变源。参数被 provider 接受不等于执行范围一定满足，执行前后都要核验。

安装源仅允许本地明确配置并校验身份的 community 源；不自动新增、更换、重置信任或接受源协议。哈希/包校验失败必须停止，不能用忽略安全校验参数重试。安装包自身仍是外部程序，本产品不是其OS沙箱。

官方依据（2026-10-22 阅读，实际接口仍待 T0 验证）：[PackageManager IDL](https://github.com/microsoft/winget-cli/blob/master/src/Microsoft.Management.Deployment/PackageManager.idl)、[安装](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)、[更新](https://learn.microsoft.com/en-us/windows/package-manager/winget/upgrade)、[卸载](https://learn.microsoft.com/en-us/windows/package-manager/winget/uninstall)。

## 5. 权限、协议和执行生命周期

主程序及模型保持普通权限。不建立持久管理员代理，不把索引服务变成维护服务。特定安装器正常提升由 Windows 交互处理；用户拒绝后停止，不循环弹窗。主程序被管理员启动时不自动获得“允许所有维护”的授权。

对于必须由产品执行的固定提权动作（如 provider 证明 DNS 清理确需提升），只考虑一次性、固定动作、校验父请求和计划的窄 helper，禁止传任意命令/注册表路径。没有受控环境证据前该能力不可用；不将 helper 作为第四期默认基础设施。

状态建议：prepared → awaiting_local_confirmation → dispatching → downloading/installing/removing → awaiting_user/awaiting_reboot → verifying → verified/partial/failed/unknown。来源、版本、范围或协议改变使原计划失效；不在原确认下换一个包或安装器。

- 确认90秒过期；派发后的执行可以长于90秒，不能把确认期限错当安装超时。
- 进度由执行层跟踪，模型不循环轮询。UI 发有界进度和阶段，百分比未知就显示阶段。
- 软观察预算初值15分钟，超出转“仍可能执行/待核对”，不强杀安装器、不擅自撤销确认。
- 取消下载不等于取消安装；请求取消和 provider 确认终止是两个字段。无法证明已停则 unknown，仍保留占用/核对入口，不启动下一维护动作。
- 若退出产品时仍有外部安装器，提示可能继续并保留回执；不偷偷后台重启 agent，不伪称已撤销系统变化。
- 需要重启时记录 awaiting_reboot，用户自行决定；不自动重启电脑，不将未重启状态报成完整可用。

## 6. 启动项维护

先支持当前用户 Startup 文件夹中普通 .lnk 的禁用与“恢复本产品禁用过的条目”。使用已核验身份和同卷、受控保留目录移动；不删除目标程序、不修改快捷方式参数、不运行快捷方式、不越过重解析点。

确认卡明确：“影响下次登录时此快捷方式是否被启动，不结束当前程序，也不保证所有其他启动来源被禁用。”同应用可能还有 Run/服务/任务等来源，必须说明。

禁用前记录原路径、条目身份、保留目录和内容/属性核验依据；执行前复核、目标冲突拒绝。恢复只回到原位置，旧位置被占或文件变化时不覆盖。进程崩溃利用逐项移动回执核对，不自动重复移动。

StartupApproved 二进制值、机器级 Run/服务/计划任务不做写入；用户级 Run/RunOnce 也先只读和固定设置页引导，不自行删注册表值。这样不声称完整覆盖所有开机启动方式。

固定系统页面跳转只报告 Windows 是否接受打开，不报告用户已完成设置；用户回来后可重新查询，但窗口被打开不是写入结果证明。

## 7. 有限网络维护

首批仅设计“清理本机 DNS 解析缓存”，执行前卡片说明影响本机所有应用的缓存、不可恢复原缓存、不会改变DNS服务器/代理/IP配置，也不保证网络恢复。

T0 验证受支持原生 API/固定 provider 的权限与返回语义，禁止经模型提供命令。若本机要求提升而无已验证路径，返回 elevation_required 并提供固定系统页面/说明，不尝试通用管理员Shell。

执行前保存诊断参照的 endpoint_ref 和时间；操作后只报告“API已接受/返回失败”，然后可按原已批准目标做只读复测，分别显示前后事实，不能仅凭错误消失认定因果。复测扩大端点/协议必须重新确认联网范围。

不自动释放/续租 DHCP、禁用网卡、重置 Winsock/TCP、删除证书、改代理或DNS服务器，也不因安装下载失败自动清缓存。更深网络修复如有实际需求，另立明确原值/恢复和失联处理的方案。

## 8. 维护契约与工具

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `software_search` | query、source_ref、installed/catalog/both、limit/cursor | 结构化软件发现，不接受下载URL |
| `software_inspect` | package_ref | 版本、源、范围、已装状态及支持动作 |
| `software_install` | package_ref、已解析version_ref、scope枚举 | 准备固定方案并等待本地确认 |
| `software_upgrade` | installed_ref、version_ref | 单实例更新及核验 |
| `software_uninstall` | installed_ref | 单实例卸载及核验 |
| `startup_change` | startup_ref、disable/restore | 仅受支持条目、明确计划、本地确认 |
| `network_maintenance` | kind=flush_dns_cache、可选已批准endpoint_ref | 固定动作、本地确认及独立复测 |

引用由本地查证产生，默认5分钟过期；准备时检查最新状态，计划变化再确认。工具无 confirmed、admin、command、args、raw_registry、force、accept_all_agreements 参数。

只读工具受现有共享策略控制；本地维护可不向模型发送事实。联网软件目录查询另有明确来源说明，不把“本地共享关闭”当作断网或允许任意联网。模型投影排除安装路径、原生用户身份、确认token、协议全文和原始installer日志。

安装器协议可能是长文，UI给标题、版本、来源及本地查看；协议接受只来自本地确认或安装器界面。不能让模型概括一句“无风险”代替协议同意。

## 9. 架构与资源控制

新增窄 `software` 模块（catalog/installed/provider/plan/verify），通过小型类型化 adapter 隔离 WinGet。`startup` 和 `network_maintenance` 各自固定 provider；复用共享确认/日志语义，但不把第二期 `application_actions` 扩成 action:string 的万能分发器。

复用既有 SQLite 回执基础，增加维护类型/版本字段和迁移测试。计划记录：来源/包身份、版本/范围、前置事实、动作、风险、权限、协议摘要身份、session/execution/config修订与期限。明确哪些字段仅本地。

同一桌面进程一次一项维护写操作。等待提升、安装器或重启核对期间，模型不能以“超时”为由开始第二项维护；可取消等待和查看结果。不要为此阶段顺带并行化所有旧工具或引入工作流引擎。

每次目录查询最多50条，原始日志每操作最多1MiB后轮转；回执沿用有界存储，unknown/awaiting_reboot不可因到期自动当完成删除。长期未解决项提供明确人工归档，归档不代表成功，也不授予重放权。

派发前先写可靠dispatching回执，写失败不执行；崩溃恢复只读核对，不重放。包版本/范围一致只能证明当前状态，不能证明上次崩溃前的动作归因。操作结果未知时先核对，再由用户明确新请求决定是否新建计划。

## 10. 实施任务和验收

| 任务 | 交付 | 必要验收 |
| --- | --- | --- |
| T0 provider实验 | 固定WinGet版本/接口、权限/协议/取消/身份矩阵；启动项和DNS可行性 | 只读先行；写操作在独立Windows测试环境，记录前后状态 |
| T1 目录与安装状态 | 精确候选/已装关联、absent/unknown区分 | 重名、多版本、未知范围、源失效、安装状态滞后 |
| T2 单软件安装 | 固定方案/本地确认/进度/核验（4A） | 已装不重复、版本漂移失效、拒绝协议/提升、断网、取消/重启/日志失败 |
| T3 更新与卸载 | 单实例闭环（4B） | 旧版仍在、需要退出、重启待核对、卸载数据选项、无自动回滚保证 |
| T4 启动项禁用恢复 | 受支持.lnk保留/恢复（4C） | 夹具、同名冲突、条目替换/链接、取消/崩溃、不影响当前进程 |
| T5 DNS缓存维护 | 固定请求/回执/独立复测（4D） | 模拟失败/提权拒绝/取消、真实隔离机器缓存状态、无自动网络重置 |
| T6 集成交付 | 双语卡片、模型协议、恢复、来源绑定 | 第一至三期相关回归，核心/UI测试、必要构建和独立状态记录 |

执行顺序 T0 → T1 → T2 交付4A → T3交付4B → T4/T5分别交付 → T6整期记录。每批完成必要自测后小步提交；没有本轮批准不由该文档推导实施、真实安装或发布授权。

确定性测试用模拟provider和虚构包；真实装卸只用独立Windows虚拟机/明确隔离试验环境及专用无害测试包，记录快照和恢复步骤。不能在工作机随意装卸真实软件验证。安装器取消、权限提升和系统重启结果需实际证据，模拟不能冒充实机通过。

固定自然语言用例至少：未装且可靠匹配；已装不更新；安装状态未知；同名多源；明确选定版本；更新需退出应用；卸载数据选项；拒绝提升；取消后安装器仍运行；重启待核对；来源协议改变；恢复启动项冲突；DNS清理不保证联网；诊断高占用不自动维护。

## 11. 完成状态与后续产品边界

4A–4D必要能力及T6自测均有证据才标第四期READY；provider不足、真实安装环境缺失或必要结果核验不可靠时标BLOCKED/NOT_VERIFIED，并可交付已完成子范围。独立测试与评审按用户触发，准备真实数据试用时明确风险并建议对应验证。
