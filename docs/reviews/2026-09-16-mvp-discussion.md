# Dao-Shell MVP 两轮讨论记录

日期：2026-09-16（Asia/Shanghai）

方式：使用 Codex 与 ChatGPT 进行两轮方案交叉评审，再由项目维护者确定范围。

本文公开讨论摘要与取舍，不包含私人对话链接或消息标识。修订后的设计见 [MVP 方案](../MVP.md)。模型评审提供设计建议，维护者负责判断和实测。

## 共同前提

- LLM 是主要入口，直接搜索是小的快捷或降级入口。
- 产品范围是辅助人使用和管理电脑，不做通用 Goal、编程 Agent 或后台自主工作。
- Rust、Windows 优先、CLI 起步，核心保留平台边界。
- 当前请求内允许上下文、工具调用和多步操作。
- 本地事实、授权和结果验证不能由模型的一段说明替代。

## 第一轮：完整方案审查

Codex 提交当时的完整 MVP 方案及产品边界，重点审查范围、过度工程和技术前置条件。

对方认可主要方向、受控文件移动、资源侧先只读、有限工具循环及最小操作模型。提出两个重大分歧：

1. 应用安装包含另一套外部安装器生命周期，不应成为第一个 MVP 必须完成的条件。
2. WinGet COM 不应成为整个 M0 的前置条件，文件闭环没有必要等待它。

另外建议简化文件操作恢复、考虑本地意图分类来缩减工具集合，并把卡顿诊断的产品承诺收紧到资源压力观察。

Codex 的判断：接受两项重大调整；继续保留文件移动。对 Unknown 与 classifier 两项不直接照单全收，带具体反例进入第二轮。

## 第二轮：回应分歧并复核

Codex 提交修订范围、工程解耦方式，以及两项保留意见。

| 议题 | Codex 提议 | 对方复核 |
| --- | --- | --- |
| 首版范围 | 文件真实操作闭环为主，资源观测辅助；应用链路独立后移 | 同意，消除了首版范围的重大分歧 |
| 技术前置 | M0a 核心验证与 M0b 应用验证分开；Everything 可先用扫描替代 | 同意，COM 和索引依赖均不应卡住文件主线 |
| WinGet 接口 | COM 优先验证，但精确 CLI 与独立结果查证也可接受 | 同意，重点是身份、参数和证据，不是接口形式 |
| 文件 Unknown | rename 已发生、回执未落盘时崩溃，重启后仍可能不知道结果；只做最小记录与核对 | 接受该反例，认可保留 Unknown，同时建议逐项记录 |
| 意图分类 | 不把自然语言 classifier 作为授权可信根；本地检查能力、范围、对象、确认和前置条件 | 接受，不再要求新增 classifier |
| 资源承诺 | 观察当前资源压力并解释可能原因，不保证完整根因诊断 | 同意 |

第二轮回复对“未解决的重大设计分歧”的原话为：

> 目前没有。

对方还指出两条值得补入的细节：

- `Unknown` 应能记录到单个文件，和成功、未开始的条目并列展示。
- 文件打开属于请求交接，其可验证程度与文件移动不同。

Codex 接受这两条建议。落到文档时进一步明确：批次仍有未知项时保留 Unknown 并展示数量；搜索与观测说明覆盖范围；打开请求只反馈系统是否接受，不宣称文档已经显示。这些是共识后的文档落实细节，不代表对方逐字审查了本地文件。

## 讨论结论

**双方目前没有重大设计分歧，可以以修订方案作为实现起点。**

v0.1 的必交付范围为：

1. 自然语言找文件、选择候选、打开文件。
2. 同卷、小批量、明确确认且可核验的文件移动。
3. 当前资源压力与进程观测，以及有证据范围的解释。
4. 小型无模型搜索入口与 Windows 分发验证。

应用能力仍属于产品方向，但独立安排；不再为了完成应用安装而推迟上述闭环。

## 留待实测的问题

- Windows 文件身份、句柄、重命名和重解析点的实际处理。
- Everything 结构化输出、中文与编码、索引过期和大结果分页。
- 异步取消与阻塞文件调用之间的真实边界。
- 系统指标的采样及 `sysinfo` 字段语义。
- 模型处理中文时间、连续指代、工具调用和消歧的稳定性。
- 干净 Windows 环境中的依赖发现、模型配置、数据目录及分发体验。
- 独立应用里程碑中的 WinGet COM/CLI 成本与安装核验来源。

两轮模型讨论只形成设计共识，没有验证实现正确性或上述接口的本机可用性。本次未开始编码，也没有执行安装、文件整理或系统设置修改。
