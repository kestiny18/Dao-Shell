# 当前桌面 UI 的用户体验审核

日期：2026-11-02。范围：当前源码与当前发布构建的真实窗口；审核首页、模型设置、通用设置及源码中的权限、搜索、维护和确认流程。主 Agent 体验审核，非独立 Tester/Reviewer 或用户研究；不修改生产代码、不提交模型请求、不执行维护。

## 结论

当前界面已有一致的配色、卡片和折叠详情，但信息架构更接近能力验证工作台。普通用户需要先理解模型、搜索机制、权限范围、操作目标和回执，才能完成一个任务。主要问题是默认暴露的概念与决策过多，不能只靠视觉美化解决。

## 优先问题

| 优先级 | 观察与依据 | 对用户的影响 | 建议 |
|---|---|---|---|
| 高 | 真实首页底部常驻短时诊断、应用操作下拉框、目标查找、回执及清理、文件搜索、电脑状态查询、输入框；1040×760 窗口中占接近四成高度。见 desktop/ui/index.html 的 entry-footer。 | 用户必须先替系统选择内部执行路径，内容区域被挤压；一句话入口的承诺不突出。 | 默认只保留输入、发送和必要状态；任务相关操作出现在结果卡片中，其他入口放入一个“工具”入口。 |
| 高 | 首页同时有启动提示、两层标题、标语、四张指标卡片、磁盘及多组详情；当前未配置状态只有文字提示去设置，没有直接完成下一步的按钮。 | 初次打开不容易判断先做什么，系统运行时长和架构先于用户任务占据位置。 | 首屏明确“找文件 / 查看电脑状态 / 管理应用”，给直接动作；缺模型时提供“连接 AI 助手”，无模型的本地搜索仍可直接开始。 |
| 高 | 通用与外观页面首先展示每次请求 token 上限、本次运行 token 预算、输出参数 Auto / max_tokens / max_completion_tokens。见 index.html settings-general。 | 普通用户无法判断数值与选择的实际含义，也难以找到语言和外观。 | 语言、外观优先；日常展示“回答长度”和清楚的用量状态。运行预算、精确 token、兼容协议放到 AI 助手的高级设置，保留原有代码保护。不要把 token 限额包装成金额硬上限。 |
| 高 | 多处术语直接面向用户：资源快照、整机口径、已登记应用、操作回执、查找操作目标、兼容目录、CLI 可写目录、模型执行上下文。 | 用户需要学习实现词汇，难以由名称推断结果。 | 使用“解释电脑状态”“应用列表”“操作记录”“选择应用”“搜索位置”“请重新描述要找的文件”；技术定义放在可展开详情。只保留与当前决定有关的解释。 |
| 高 | 权限页混入 CLI 可写目录和桌面不支持的移动说明；搜索页同时解释 NTFS、全盘服务、兼容目录、索引生命周期。 | 搜索位置、查看权限、索引加速等不同概念混在一起，用户被迫维护系统。 | 用“在哪里找文件”和“哪些信息可以发送给 AI”组织日常设置。索引机制自动处理，异常时展示简短影响与推荐操作，服务管理与 CLI 放高级设置。 |
| 高 | 界面隐私说明仍写发送 PID，但 src/observation.rs 的 model_projection 白名单不发送 PID；访问页仍写桌面只提供查找/元数据/确认打开，与当前应用维护能力不符。 | 用户无法准确判断会分享什么、产品能改变什么，影响信任。 | 先核对所有能力、分享范围和风险文案，保证与当前代码一致；恢复和风险提示不能为了简洁而失真。 |
| 中 | 侧栏会话与顶部标签重复表达同一组会话；当前窗口多个“新会话”难以区分；导出全部历史长期占据侧栏大按钮。 | 导航重复，低频操作抢占空间。 | 先确定唯一主要会话导航；会话更多菜单承载重命名/删除，历史导出放历史管理或设置。若保留标签，需明确它承担的独立任务。 |
| 中 | 模型设置在空状态先呈现默认模型与模型清单两个选择器，技术状态说明多于首次连接引导。 | 用户尚未添加模型就要理解默认选择、已添加模型及上下文重建。 | 空状态只有“连接 AI 助手”和“先使用本地功能”；连接后再展示当前助手及切换入口，多个模型管理按需出现。 |
| 中 | 维护确认直接拼接 operation、source_id、package_id、scope、architecture；历史也直接显示 operation 和底层状态。见 maintenance.js。 | 即使安全确认完整，用户仍不容易看清到底操作什么、后果是什么。 | 确认主要内容为动作、应用名/版本、影响、是否可恢复和明确动作按钮；来源标识/架构放技术详情。未知结果应说明“暂时无法确认是否完成”，给唯一合适的核对入口，不能误报失败或完成。 |

## 建议的信息架构

- 首页：一个突出输入区；少量任务入口；当前任务结果。电脑详细指标不与所有工具挤在首屏。
- 电脑状态：资源、磁盘、应用、网络的可读信息；按需查看详情和启动诊断，不凭单次高占用生成健康结论。
- 设置：搜索位置、AI 助手、隐私、外观与语言、高级。高级承载协议参数、CLI、索引服务、详细诊断。
- 操作反馈：优先回答“发生了什么、对我有什么影响、下一步做什么”；完整证据可展开查看，代码边界继续严格执行。

## 实施顺序建议

1. 先统一准确文案，移走默认可见的技术参数和全局工具栏，补齐空状态的直接下一步。
2. 再重组首页、设置和会话导航，按真实任务重排确认与结果卡片。
3. 最后调整留白、字号、密度与视觉细节。先做可试用原型，用“首次找文件、解释电脑状态、连接助手、取消一次操作、找回历史”验证路径。

本报告是审核建议，不授权直接重做界面；当前源码和已交付安装包未因本次审核改变。视觉观察基于当前窗口，非多个分辨率、屏幕阅读器或真实新用户可用性实验。
