## 先做只读预检

在另一台机器使用普通用户 PowerShell，记录 Windows 版本、CPU 架构及以下输出。无需密码或 API Key。

```powershell
winget --version
Get-AppxPackage Microsoft.DesktopAppInstaller | Select-Object Name, Version, Architecture
```

收到便携测试包时，先在解压目录运行 `.\phase4_readonly.exe`。源码仓库中的同一候选探针为 `target/debug/examples/phase4_readonly.exe`；有源码/工具链时可构建：

```powershell
.\scripts\dev.ps1 build -CargoArgs @('--locked','--example','phase4_readonly')
.\target\debug\examples\phase4_readonly.exe
```

探针只尝试原生接口激活/枚举来源及固定 WinGet export；可能读取本机安装清单、访问已配置来源，不安装、更新、卸载、接受来源协议或清理 DNS。终端最终只输出可用性、来源元数据和条目数量，不输出软件明细。

**如果 `native.available` 为 false，先把 JSON 结果反馈回来，软件装卸测试停止于此。** 不要为通过测试而重装 AppInstaller、改注册表、开启管理员 Shell 或执行来源协议的自动接受命令。CLI 可用不等于原生接口可用。

## 隔离运行候选

候选为 `desktop/src-tauri/target/debug/dao-shell-desktop.exe`，与现有发布版本分开保存。运行前使用专用配置和 WebView 数据目录；配置隔离并不隔离真实软件、Startup 和 DNS。

便携测试包包含 `Start-Trial.ps1`，它已设置候选专用的配置和 WebView 目录。使用该脚本启动；手动启动时先按下列方式设置环境，避免直接使用日常配置。

```powershell
$phase4Root = Join-Path $env:LOCALAPPDATA 'DaoShellPhase4Trial'
New-Item -ItemType Directory -Path $phase4Root -Force | Out-Null
$env:DAO_SHELL_DESKTOP_CONFIG = Join-Path $phase4Root 'dao-shell.json'
$env:WEBVIEW2_USER_DATA_FOLDER = Join-Path $phase4Root 'webview'
& '.\dao-shell-desktop.exe'
```

在文件会话下展开“软件与系统维护”。本地入口不需要模型；自然语言验证还需要配置模型并明确允许电脑信息共享。目录查询另需勾选本次会话的 WinGet 来源授权。确认卡片必须列出实际包身份、版本、范围和影响，协议有正文时另行勾选接受。

## 软件用例（仅在原生预检成功后）

先选一款可随时丢弃数据、能够重装的测试软件，记录精确包 ID、当前版本、目标版本、范围及已知安装状态。当前原型发现入口只提供当前用户范围、目录默认版本；其他范围、任意历史版本选择尚未交付。不能用没有候选推断未安装。

| 用例 | 操作 | 应记录的结果 |
| --- | --- | --- |
| 拒绝方案 | 查询后选择安装，取消确认 | 没有安装器/UAC、没有新增安装；本轮不换方案重试 |
| 协议拒绝 | 对带协议的软件不勾选接受 | 确认按钮不可用；取消后不派发 |
| 明确安装 | 核对身份/版本/用户范围后确认 | 安装器行为、最终回执、系统独立查看的真实版本/范围 |
| 已安装 | 再查询同一包 | 不提供重复安装；状态不可靠则停止 |
| 更新 | 已装旧版本时选择更新 | 明确当前/目标版本；不能静默关闭应用；保留失败/待交互/待重启状态 |
| 卸载 | 选择一次明确的测试安装 | 确认实际已装版本；卸载器数据选项由人决定；完成后独立核对 |
| 取消/拒绝提升 | 安装器或 UAC 出现时取消 | 不自动重试、提权或强制结束；不能把取消等待当作安装器停止 |
| 未知/重启 | 仅在可恢复环境中中断客户端或遇到重启要求 | 重启客户端不重放；显示未知/待重启并阻止后续写操作 |

软件未知结果的自动空闲证明和解除阻塞路径尚未完成；遇到该状态时保留回执并反馈，不删除日志或再次安装以“修复测试”。原生来源协议发生变化也会停止，不自动接受。

## 启动项用例

只在专用测试 Windows 账户/可恢复环境中，手工创建一个指向无害系统程序的专用 `.lnk`，放入该账户 Startup 文件夹。不要选择日常软件的原有快捷方式，也不要为验证而注销当前工作账户。

1. “查询可禁用/恢复的启动项”，选择测试快捷方式并取消；确认文件仍在原位。
2. 重新选择并确认禁用；原快捷方式应移至同级 `DaoShellDisabledStartup` 保留目录，当前运行的程序不应被停止。
3. 重新查询，确认恢复；应回到原路径，文件身份和摘要保持一致。
4. 禁用后在原路径手工创建同名测试快捷方式，再恢复；必须拒绝覆盖，保留双方文件。该失败可能进入未知状态，先保存回执，不连续重试。
5. 在单独可恢复试验中替换或修改保留文件；重新查询不应把它作为可恢复的原文件。

保存测试文件路径、前后存在状态、回执和操作时间。内容/身份检查由代码执行；界面显示“登记已移动”不等于已经验证下次登录行为。

## DNS 用例

DNS 清理影响整台测试机器，原缓存不可恢复。只在不会打断正在使用的任务时执行一次。

1. 用系统工具只读查看缓存及当前 DNS/代理/IP 配置，按需要做脱敏记录。
2. 点击“准备清理 DNS 缓存”后取消，检查没有清理成功回执。
3. 再次发起，读完影响说明后明确确认；记录系统 API 报告的成功/失败及时间。
4. 独立只读查看缓存及配置；系统可能立即重新填充缓存，不能要求缓存永久为空。
5. 若需要联网复测，在诊断入口另行批准同一目标再测。清理成功不等于网络恢复，也不能证明故障因果。

不运行 `ipconfig /flushdns` 等命令作为产品操作的替代证据，不执行网卡禁用、DHCP 续租或网络重置。
